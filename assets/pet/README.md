# Custom buddy sprites

The app includes robot, cat, and knight characters drawn directly in Qt.
No downloads or image files are needed. All characters have interaction poses.

To replace a character, create a matching subfolder here: `robot`, `cat`, or
`knight`. Put square transparent PNG frames in that folder, using a fixed canvas
and these names:

- `idle_01.png`, `idle_02.png`, ...
- `walk_01.png`, `walk_02.png`, ... (character faces right; left is mirrored)
- `sleep_01.png`, `sleep_02.png`, ...
- `excited_01.png`, `excited_02.png`, ...
- `drag_01.png`, `drag_02.png`, ...
- `landing_01.png`, `landing_02.png`, ...
- `wave_01.png`, `wave_02.png`, ...
- `pet_01.png`, `pet_02.png`, ...
- `eat_01.png`, `eat_02.png`, ...
- `dance_01.png`, `dance_02.png`, ...
- `jump_01.png`, `jump_02.png`, ...

Version 5 adds 24 states: stretch, spin, flip, roll, sneeze, scared, laugh, sit,
balance, tiptoe, run, climb, slide, skate, bounce, magic, umbrella, juggle, groom,
salute, facepalm, lean, hang, sneak. Use the same lowercase numbered PNG convention
for each. All 49 states have built-in drawing fallbacks. Real folder peeking also
uses the built-in character, aligned with the native icon.

Frames are loaded in alphabetical order. Pad numbers to keep the order correct.
Use a 24×24 or 32×32 pixel canvas. Nearest-neighbor scaling preserves sharp pixels.
Each state without valid PNGs uses the selected built-in character. Legacy
robot frames in this folder still work if no `robot` subfolder exists.
Parachute animation always uses the built-in character and canopy, so the ropes
and extra canvas align correctly; custom parachute frames are not used.
Folder portals also use the built-in face for peeking. Eye movement is drawn
into the built-in characters; custom look frames are played as provided.
Restart the app after replacing sprites.
When building an EXE, add sprites first; they are bundled by Build_EXE.bat.
